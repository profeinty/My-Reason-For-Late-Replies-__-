# Bot tests on a stand-in game

A fake MonsoonSIM game (dashboard, rent, vendor, marketing, B2B offers and sales orders, shipping, machines, production and Web Market screens, forms that take orders, and Transactions screens where each request waits for approval) for testing the bot in `reader.js` without touching a real game. Plans use the format in [docs/plan-format.md](../docs/plan-format.md).

    npm install playwright            # once, anywhere on your computer
    node test/server.mjs 8791 reader.js &
    node test/test.mjs 8791 test      # set CHROMIUM=/path/to/chromium to use your own browser

Fail modes on the server: `?fail=<CMD>` (the game refuses), `COD` (cash on delivery), `E500:<CMD>` (the order goes through, then the game answers with an error page). More of the game: `&so=1` (won orders and a web order to ship), `&wfg=1` (goods in the warehouse), `&mach=1` (two machines with a production history), `&cash=N`. Like the real game, list screens (Transactions, B2B offers, B2B sales orders) read under 1 s apart answer "Slow down"; `&slow=N` refuses the next N anyway. Approvals: `&noscript=1` (rows with a ✓ but no approve script), `&approvefail=once|all` (the game refuses approvals). `/day?d=N&offers=1` starts day N with the B2B offers open again.

Cases: A full plan run for real, B practice run (nothing sent), C screen check, D Start opens the calculator (`calc-stub.html`) inside the game tab and runs its plan, D2 an older calculator that doesn't answer there opens in its own tab, D3 a locked one shows and waits for the passcode, E the game refuses an order, F cash on delivery, G plan doesn't match the game's cash, H release, shrink, vendor price and B2B limits, I below the bulk lot price, J lost answer counted as bought, M reader loaded again the same day sends nothing twice, N Run by itself starts the bot with no click, P bid history with every team's price (Load More), Q shipping won and web orders exactly as the game's page does, Q2 practice and autoShip off ship nothing, Q3 2 refused shipments stop the bot, R machines fit the floor and the budget, R2 production and machine status, S Web Market buys and our own post at the shop price, S2 a post leaves what won orders need, T approvals with no approve script and one refused, T2 every approval refused, T3 the next day's approvals, U refused list screens read again, V a new day: the B2B deal first, then the rest of the plan.

The stub answers like the calculator; `&stub=old` makes it answer only a tab that opened it (like calculator v36), `&stub=locked` makes it say it's locked until `unlock()`.

Result for reader v11: all 170 checks pass. A 15-step day sends every order in about 2 s; its approvals follow in the background, about 1 s per Transactions screen (13 s in all on a game's first day, when the bot also learns where each kind of request goes). On a new day the B2B deal goes out about 1.1 s in and the rest of the plan about 2.4 s in.

`node test/e2e-calc.mjs 8791` runs the real calculator (`calc/index.html`, unlocked with a test passcode on that browser only) with the bot on the stand-in game: Start opens it (inside the game tab; `EXPECT=tab` when the calculator only works in its own tab), it makes the day's plan and the bot runs it. `CALC_FILE=<path>` on the server serves another copy of the calculator. It fails on page errors, a price or cancel command, or a step the bot doesn't know or fails.
